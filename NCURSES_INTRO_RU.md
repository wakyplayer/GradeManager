# Основы Ncurses для GradeManager

Эта заметка нужна, чтобы выучить ровно столько `ncurses`, сколько нужно для простой терминальной UI-версии этого проекта.

Цель не в том, чтобы сделать красивое приложение. Цель в том, чтобы заменить длинное меню через `printf` на более аккуратный текстовый экран, где пользователь нажимает клавиши, выбирает действия и видит результат.

## Что такое ncurses?

`ncurses` - это библиотека для языка C, которая помогает рисовать внутри терминала.

Обычная C-программа в терминале часто работает так:

```c
printf("Menu\n");
scanf("%d", &choice);
```

Это просто, но экран постоянно прокручивается вниз.

С `ncurses` программа может:

- очищать экран
- печатать текст в нужной строке и колонке
- читать одну клавишу за раз
- рисовать рамки и простые меню
- обновлять только нужные части экрана

Это все еще терминальная программа. Это не обычное оконное приложение с кнопками и мышкой.

## Почему это подходит для этого проекта

Полноценный графический интерфейс на C потребовал бы более сложный фреймворк. Это слишком много новой сложности на этом этапе.

Для GradeManager текстовый интерфейс - хороший следующий шаг:

- программа все еще остается на C
- логика оценок остается в `grades.c`
- интерфейс можно улучшить без переписывания всего проекта
- студент учится делать простые терминальные приложения

Важно: UI не должен дублировать логику оценок.

Например, UI должен вызывать уже существующие функции:

```c
FindMax(grades, n);
FindAverage(grades, n);
CountPassed(grades, n);
CountFailed(grades, n);
SetGrade(grades, n, index, grade);
AddGrade(&grades, &n, grade);
DeleteLastGrade(&grades, &n);
```

UI - это только лицо программы. `grades.c` - это мозг программы.

## Перед началом

Не стоит начинать ncurses-интерфейс, пока основные баги в логике не исправлены.

Хороший порядок работы:

1. Убедиться, что функции для оценок работают правильно.
2. Убедиться, что добавление, редактирование, удаление, сохранение и загрузка работают правильно.
3. Только потом делать более аккуратный терминальный UI.

Это важно, потому что интерфейс может спрятать ошибки. Если логика неправильная, красивый экран все равно будет показывать неправильные ответы.

## Как подключить ncurses

В начале C-файла:

```c
#include <ncurses.h>
```

При компиляции нужно подключить библиотеку `ncurses`:

```bash
gcc main.c grades.c -lncurses -o grade_manager
```

Если будет отдельный файл для UI:

```bash
gcc main.c grades.c ui_ncurses.c -lncurses -o grade_manager
```

## Самая маленькая ncurses-программа

```c
#include <ncurses.h>

int main(void)
{
    initscr();              // начать ncurses-режим
    printw("Hello ncurses");
    refresh();              // показать изменения на экране
    getch();                // подождать одну клавишу
    endwin();               // вернуть терминал в обычный режим

    return 0;
}
```

Самое важное правило:

Если вызвали `initscr()`, потом обязательно нужно вызвать `endwin()`.

Если программа завершится без `endwin()`, терминал может выглядеть сломанным, пока вы его не сбросите.

## Главные функции ncurses

### `initscr`

Запускает ncurses.

```c
initscr();
```

Вызывается один раз в начале UI.

### `endwin`

Останавливает ncurses и возвращает терминал в обычный режим.

```c
endwin();
```

Вызывается перед выходом из программы.

### `printw`

Похоже на `printf`, но печатает на ncurses-экране.

```c
printw("Grade: %d", grade);
```

### `mvprintw`

Переходит в нужную строку и колонку, потом печатает текст.

```c
mvprintw(2, 4, "Grade Manager");
```

Это значит:

- строка `2`
- колонка `4`
- напечатать `"Grade Manager"`

Строки и колонки начинаются с `0`.

### `clear`

Очищает экран.

```c
clear();
```

Используйте это перед тем, как рисовать новый экран.

### `refresh`

Показывает изменения.

```c
refresh();
```

В ncurses функции рисования сначала подготавливают экран, но пользователь может не увидеть изменения до вызова `refresh()`.

### `getch`

Читает одну клавишу.

```c
int key = getch();
```

Пример:

```c
int key = getch();

if (key == 'q') {
    // выйти
}
```

## Полезная настройка

Большинство ncurses-программ начинают с такой настройки:

```c
initscr();
cbreak();
noecho();
keypad(stdscr, TRUE);
```

Что это значит:

- `cbreak()` позволяет получать ввод сразу, без ожидания Enter
- `noecho()` не показывает на экране клавиши, которые пользователь нажимает
- `keypad(stdscr, TRUE)` позволяет читать стрелки на клавиатуре

В конце:

```c
endwin();
```

## Рисование текста в нужных местах

Экран терминала можно представить как таблицу.

Левый верхний угол:

```text
строка 0, колонка 0
```

Пример:

```c
clear();
mvprintw(0, 0, "Grade Manager");
mvprintw(2, 0, "1 - Print grades");
mvprintw(3, 0, "2 - Show max");
mvprintw(4, 0, "0 - Exit");
refresh();
```

Так меню каждый раз рисуется в одном и том же месте.

## Простые фигуры

### Один символ

```c
mvaddch(5, 10, '*');
```

Это рисует `*` в строке `5`, колонке `10`.

### Горизонтальная линия

```c
mvhline(1, 0, '-', 30);
```

Это рисует 30 символов `-` в строке `1`.

### Вертикальная линия

```c
mvvline(2, 0, '|', 10);
```

Это рисует 10 символов `|`, начиная со строки `2`, колонки `0`.

### Рамка вокруг экрана

```c
box(stdscr, 0, 0);
```

`stdscr` значит главный экран.

Полный пример:

```c
clear();
box(stdscr, 0, 0);
mvprintw(1, 2, "Grade Manager");
refresh();
```

## Простой цикл меню

Вот базовая идея для проекта:

```c
#include <stdbool.h>
#include <ncurses.h>
#include "grades.h"

static void DrawMenu(void)
{
    clear();
    box(stdscr, 0, 0);

    mvprintw(1, 2, "Grade Manager");
    mvprintw(3, 2, "1 - Print grades");
    mvprintw(4, 2, "2 - Show max");
    mvprintw(5, 2, "3 - Show average");
    mvprintw(6, 2, "4 - Show passed students");
    mvprintw(7, 2, "5 - Show failed students");
    mvprintw(8, 2, "0 - Exit");

    mvprintw(10, 2, "Press a key:");
    refresh();
}

int main(void)
{
    int grades[] = {80, 70, 95};
    int n = 3;
    bool running = true;

    initscr();
    cbreak();
    noecho();
    keypad(stdscr, TRUE);

    while (running) {
        DrawMenu();

        int key = getch();

        clear();
        box(stdscr, 0, 0);

        switch (key) {
        case '1':
            mvprintw(2, 2, "Grades:");
            for (int i = 0; i < n; i++) {
                mvprintw(3 + i, 2, "%d", grades[i]);
            }
            break;

        case '2':
            mvprintw(2, 2, "Max grade: %d", FindMax(grades, n));
            break;

        case '3':
            mvprintw(2, 2, "Average: %.2f", FindAverage(grades, n));
            break;

        case '4':
            mvprintw(2, 2, "Passed students: %d", CountPassed(grades, n));
            break;

        case '5':
            mvprintw(2, 2, "Failed students: %d", CountFailed(grades, n));
            break;

        case '0':
            running = false;
            break;

        default:
            mvprintw(2, 2, "Unknown option");
            break;
        }

        if (running) {
            mvprintw(12, 2, "Press any key to return to menu");
            refresh();
            getch();
        }
    }

    endwin();
    return 0;
}
```

Это не финальный код проекта. Это учебный пример.

Главная идея: меню вызывает `FindMax`, `FindAverage`, `CountPassed` и `CountFailed`. Оно не считает эти значения заново внутри UI.

## Чтение чисел в ncurses

Для простого выбора пункта меню достаточно `getch()`.

Для ввода настоящего числа можно сначала сделать так:

```c
echo();
nocbreak();

char text[20];
mvprintw(5, 2, "Enter grade: ");
getnstr(text, sizeof(text) - 1);

cbreak();
noecho();
```

Потом текст можно превратить в число:

```c
int grade = atoi(text);
```

Но `atoi` не очень строгая функция. Позже лучше использовать `strtol`, чтобы программа могла отвергать плохой ввод вроде `abc`.

Для этого учебного проекта сначала держите ввод простым:

1. Спросить текст.
2. Превратить текст в число.
3. Проверить, что число от `0` до `100`.
4. Если число неправильное, показать ошибку.

## Как показать сообщение

Небольшая вспомогательная функция может сделать UI чище:

```c
static void ShowMessage(const char *message)
{
    clear();
    box(stdscr, 0, 0);
    mvprintw(2, 2, "%s", message);
    mvprintw(4, 2, "Press any key to continue");
    refresh();
    getch();
}
```

Потом можно использовать так:

```c
ShowMessage("No grades available");
```

Это лучше, чем много раз повторять один и тот же код рисования экрана.

## Более удобная структура проекта

Разделяйте файлы по задачам:

```text
grades.h          объявления функций для логики оценок
grades.c          логика оценок
main.c            запускает программу
ui_ncurses.c      ncurses-меню и экраны
```

UI-файл может подключать:

```c
#include "grades.h"
#include <ncurses.h>
```

UI должен спрашивать ответы у логики оценок:

```c
int max = FindMax(grades, n);
double average = FindAverage(grades, n);
```

UI не должен копировать циклы из `grades.c`.

Плохая идея:

```c
// Не дублируйте это в UI.
int max = grades[0];
for (int i = 0; i < n; i++) {
    if (grades[i] > max) {
        max = grades[i];
    }
}
```

Хорошая идея:

```c
int max = FindMax(grades, n);
```

## Частые ошибки

### Забыли `refresh`

Если ничего не появляется, проверьте, вызвали ли вы:

```c
refresh();
```

### Забыли `endwin`

Если терминал странно выглядит после завершения программы, возможно, программа не вызвала:

```c
endwin();
```

### Смешивание `printf` и ncurses

После `initscr()` лучше не использовать обычный `printf` для UI.

Используйте:

```c
printw();
mvprintw();
```

вместо него.

### Дублирование логики

Не переписывайте расчеты оценок внутри UI.

UI должен вызывать функции из `grades.c`.

### Первый UI слишком большой

Сначала сделайте только:

- нарисовать меню
- прочитать клавишу
- показать один результат
- вернуться в меню
- выйти аккуратно

Потом добавляйте остальное.

## Маленькое упражнение для урока

Перед изменением полного проекта создайте маленький тестовый файл и попробуйте:

1. Запустить ncurses.
2. Нарисовать рамку.
3. Напечатать `"Grade Manager"` сверху.
4. Показать три пункта меню.
5. Прочитать одну клавишу.
6. Показать сообщение в зависимости от клавиши.
7. Выйти через `endwin()`.

Когда это заработает, подключайте меню к настоящим функциям для оценок.

## Главное правило

Держите это разделение понятным:

```text
grades.c      знает, как работают оценки
ncurses UI    знает, как показывать вещи на экране
```

Если UI нужен результат, он должен спросить `grades.c`.

Так проект остается проще для понимания и проще для будущих изменений.
